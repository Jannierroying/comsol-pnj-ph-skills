# PNJ/PH 总入口

波动光学任务先读并遵守[参数化扫描、计算与基本场图](references/simulation-and-display.md)：同类改参放在同一模型中，每个参数独立一个研究/参数化扫描节点，值列表用 `range(起点,步长,终值)`；实际计算后生成 `ewfd.normE^2`、Rainbow 场图。基本场图属于仿真交付，定量结果分析是独立阶段；用户暂停后处理时仍计算和生成基本场图，其余分析不自动启动。

把本 skill 当成工作流路由器。先理解用户要完成的结果，选取并读取下列**相关**子 skill 的 `SKILL.md`；随后按任务读取其 references 并执行。一个任务可能跨多个阶段，但不应每次无差别加载全部 skill。用户直接指定某个子 skill 时，尊重该选择。

- 从零用简单结构产生 PNJ 或单 PH：读 [基础模式](../comsol-pnj-ph-basic/SKILL.md)。
- 依据论文、`.mph` 或其他软件已跑模型，在 COMSOL 6.3 重建，或替换波长、几何、背景电场、介质：读 [复现模式](../comsol-pnj-ph-reproduce/SKILL.md)。
- 用户提出新机制或新结构，希望先查资料、理论论证、讨论，再做试验：读 [创造模式](../comsol-pnj-ph-create/SKILL.md)。
- 已有场数据、模型结果或截图，需要提取指标、比较或排查：读 [结果处理](../comsol-pnj-ph-results/SKILL.md)。
- 所选方案涉及金属、各向异性、GRIN、部分照明、反射、SPP 或复杂源：再读 [复杂机制](../comsol-pnj-ph-advanced/SKILL.md)。
- 指定《最终版.pdf》同心双椭圆多臂案例：在复现模式中再读 [多臂专例](../comsol-ph-multiarm/SKILL.md)。
- 建立光线追迹模型，观察折射、反射和全反射路径：读 [光线追迹](../comsol-pnj-ph-raytrace/SKILL.md)。采用gop + RayTracing和射线图；不强制使用ewfd、Wavelength研究或normE²。
- 查找可行模板、参考已验证模型，或收录用户确认的成功仿真：读 [模型参考库](../comsol-pnj-ph-examples/SKILL.md)。它是各模式共用案例库，不替代三种模式。

组合时按目标的真实依赖排序。例如论文改参任务先核对来源并建立基准，再改参并计算基本场图，在模型可计算且用户允许分析时才用结果模块做定量对照；创造任务先证据与理论筛查、同用户讨论，再试验，模型可计算且用户允许分析时才量化结果。只选择本次必要模块，告诉用户选用了哪几个及原因；不要求用户记住所有子 skill 名称。

共同约定：用户已指定参数优先；缺少常规波长、尺寸、折射率和数值参数时主动给具体初值并标明来源。波动光学模式在 COMSOL 6.3 使用 Wavelength Domain 研究，物理接口为 ewfd；光线追迹模式按其独立接口、研究和图示要求执行；按模型向导、参数、几何、定义/PML、材料、物理场、网格、研究求解、结果、验证、导出的软件顺序展开。文献值、推导值、AI 补全值和实算结果分开。没有实际求解能力或尚未运行时提供可执行方案，不宣称已经得到 PNJ/PH 或完成复现。

执行方式按用户选择：GUI 教程按软件界面次序，非 GUI 建模按模型依赖次序。通过 COMSOL MCP 工作时，先检查连接和模型列表；它可能是独立会话，不能假设其中有 GUI 里未保存的模型。若当前 MCP 缺少 PML、背景场、材料属性或波长域等写入接口，可用 COMSOL 6.3 自带模型 API 批处理补齐，再由 MCP 载入、求解和核验；向用户如实说明这种组合方式。基础二维 PNJ 的已验证做法见[基础模式 MCP 实操](../comsol-pnj-ph-basic/references/mcp-workflow.md)。

每次实际建模或处理结果前，在 `PROJECTS_ROOT` 下新建一个本次任务专用文件夹；将本次的 `.mph`、脚本、导出图、数据和验证记录存入其中，不复用上次任务的文件夹。中间文件可以先写在可用工作目录，但交付前应归集到该文件夹并核对路径。用户另行指定输出目录时，以用户指定为准。


参考已有可行模型时按需读取[模型参考库](../comsol-pnj-ph-examples/SKILL.md)。仿真完成后检查用户确认状态：有明确确认则收录案例及确认依据；只有计算成功时登记待验证，不能代替用户确认。复用时另存新任务副本，不覆盖参考模型；该案例的参数与验证范围不自动推广到其他结构。
