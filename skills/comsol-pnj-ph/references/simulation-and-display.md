# 参数化扫描、计算与基本场图

本文件的ewfd、Wavelength研究和normE²基本场图规则适用于COMSOL 6.3 PNJ/PH波动光学任务。光线追迹采用[专门skill](../../comsol-pnj-ph-raytrace/SKILL.md)的gop、RayTracing及射线图规则；不以射线图冒充电场图。目录组织、参数扫描、实际计算和分析阶段分离的约定仍适用。用户指定条件优先。

## 模型组织

同一几何拓扑、物理场和求解流程的角度、尺寸、折射率等变化，优先在同一个 `.mph` 的“研究 → 参数化扫描（Parametric Sweep）”中设置；不要每个参数值另建一个模型文件。不同扫描方向可使用同一模型的不同研究。结构拓扑、物理接口或数值方法确实不同才分模型，并说明原因。独立任务仍在 `PROJECTS_ROOT` 新建专用文件夹；同一任务的修改继续使用该文件夹。

默认每个扫描节点只选择一个参数，在该参数的“参数值列表”填写 `range(起点,步长,终值)`，例如 `range(0.2,0.1,0.9)` 表示从0.2开始、每次增加0.1、到0.9结束；单位在参数单位栏另设。所有角度必须明确为 `deg`：全局角度参数写成如 `60[deg]`，参数化扫描单位栏填写 `deg`；角度范围框必须将每一项也写明单位，如 `range(30[deg],5[deg],100[deg])`；起点、步长、终值均带[deg]，参数单位栏仍填deg。不能仅写range(30,5,100)而把角度单位隐藏在别处，也不能当成rad。不同参数必须分开设置不同参数化扫描，不把多个参数放进同一张配对值表，也不默认做所有参数的笛卡尔积。

为实现独立的单因素扫描，在同一 `.mph` 中给不同参数建立独立研究，每个研究包含自己的一个参数化扫描节点和波长域步骤；不在同一个研究里堆叠多个扫描节点而意外形成嵌套扫描。研究名称、说明及参数记录写明其余固定参数。复用同一扫描研究比较不同固定条件时，在计算前主动将固定参数改到对应值；不能把研究名称当成实际参数已经自动切换。

文献给出的不等间隔值不能静默换成等间隔范围。可在同一参数值框中使用多段range表达式，或与用户确认新范围；用户举的数字只是语法示例时不自动改论文参数。只有用户明确要求联合扫描时才另行定义联合方法和组合数量。

几何参数变化时应通过研究的外部参数化扫描重建几何和网格，不用仅针对同一网格的求解器辅助扫描代替。核对命名选择在每组几何中有效，检查旋转后嵌套与薄壳。保留全部参数解，关闭每个参数值单独保存模型；内存不足时说明限制并分组，不静默丢弃参数解。

先算目标所需的最少代表组。大范围或数值收敛扫描须符合当前任务范围，不默认扩展成几十个模型。已配置但未计算的扫描与实际已计算的扫描分别记录。

## 用户先查看设置时

用户明确说“先不计算”“只设置模型”“先查看”时，停止正在运行的研究，禁用自动计算入口，保存设置查看版 `.mph`。仍应配好研究参数扫描、波长域、求解器与场图节点（`ewfd.normE^2`、Rainbow）及数据集；只创建默认求解器不等于执行计算。不得为了核查而偷偷求解。记录已配置/已计算/中途取消的区别；原始场图在后续明确恢复计算并成功求解后才生成。用户恢复计算之前不自动重启。

## 仿真阶段必须实际计算并显示场

设置研究和扫描后，执行“计算”（API `study.run()` 或 MCP study solve），等待成功；保存包含解的 `.mph`。仅创建几何、设置参数或生成未求解模板不能称为完成仿真。

计算成功后创建二维绘图组（3D 模型用相应三维组）和表面图（Surface）：
- 表达式严格使用 `ewfd.normE^2`，直接写在表面节点，不用自定义变量 G 或 `(abs(ewfd.Ex)^2+abs(ewfd.Ey)^2)/Eamp^2` 替代。
- 颜色表选择 **Rainbow**；API 的 `colortable` 应通过当前版本读取验证。
- 数据集绑定实际求得的解，能选择对应参数值；每个已求解研究有可访问的基本场图。
- `ewfd.normE^2` 是电场模平方，通常单位为 V²/m²；不将其标成无量纲增强，也不偷偷除以 Eamp²。Eamp=1 V/m 时数值可能一致，但量纲和表达式仍不同。
- 原始场图属于仿真交付，可以保存截图/PNG供查看；不附加轨迹、阈值、拟合、统计或论文数值比较。

重载含解模型，检查研究/参数列表、实际解、场图表达式和 Rainbow 配色可读取。必要时用求解日志确认扫描全部完成。MCP 缺少建图或扫描属性写入接口时，用 COMSOL 6.3 官方模型 API 补齐，说明实际执行方式。已验证的表面节点设置为 `set("expr","ewfd.normE^2")`、`set("colortable","Rainbow")`，两者用 `getString` 读取；表面expr为标量字符串，不用getStringArray读取。参数选择属性随绘图组和版本变化，先检查节点properties，不硬套不支持的looplevelinput。求解完成先保存含解模型，再生成基本场图，避免建图失败丢失已求得的解。

## 与结果分析的边界

仿真可行性检查仅涵盖几何、选择、材料、激励、网格、求解是否成功以及原始场图是否可生成，不能据此宣称定量复现或收敛已达标。

焦点/峰值、FWHM、臂数、臂长、弯曲角、中线、坡印廷流线、光线机制、数据导出加工、采样敏感性、论文对照和光学收敛比较属于独立结果分析阶段。先确认模型可正常计算，再按用户授权启动结果处理 skill。用户说“暂停/不做后处理”时，仍进行研究计算和上述基本场图；其他分析保持暂停，只有用户明确恢复后继续，不因求解完成而自动启动。

文献定量比较需要归一化等表达式时，应在恢复分析后另行定义测量量，保留基本场图的 `ewfd.normE^2` 与 Rainbow 设置。


## 参数解与 MCP 名称核对（本次6.3实操补充）

核验参数扫描时检查实际保存解的外层参数数量，不仅核验配置值列表。当前双椭圆案例中 `getSolutioninfo().getOuterSolnum().length` 返回15，而 `getParamVals()`只返回最后一个角度值，不能用后者代表全部扫描。

MCP研究、数据集和模型参数可能按显示名称解析，与Java API标签不同；先读各工具返回的名称。当前仅一个研究时省略study_name可求解，传std1曾因名称解析失败；不得由此断言底层研究不存在。保存后重新核对model_list中的键。当前工具进度数值不保证反映已完成参数组数，等待完成状态和实际解验证；批处理同时检查日志与文件，不只看退出码。

具体参数层级、API限制、文件和验证边界见[双椭圆内核扫描案例](../../comsol-pnj-ph-examples/references/dual-ellipse-inner-rotation.md)，不把这一案例的固定条件用于全部模型。用户明确确认可行的完成模型收录[模型参考库](../../comsol-pnj-ph-examples/SKILL.md)；计算成功但未经用户确认的单独登记。
