# PNJ/PH 光线追迹

采用本 skill 建立原生 `.mph` 光线模型。默认按已跑通的 MCP + 官方 Java API 方法执行；用户指定 GUI 时按对应界面顺序操作。物理接口为 `GeometricalOptics`（gop），研究为 `RayTracing`，真空波长在射线属性设置；不套用 ewfd 的 Wavelength 研究和 `ewfd.normE^2` 场图要求。射线图是本模式的基本仿真交付。

## 工作顺序

1. 明确来源及目标。沿用用户选定波动模型的维度、坐标、几何尺寸/角度、真空波长、材料、传播方向及偏振；另列射线释放口径、条数、截止阈值和终止条件。缺少参数时主动设具体初值并说明来源。二维双椭圆可读[已完成案例](references/core-shell-60-case.md)，其他结构不照搬其60°、S或折射率。
2. 在 `PROJECTS_ROOT` 新建本次任务文件夹，保存模型、脚本、原生图及核验记录；同一任务迭代沿用该文件夹。源波动模型和参考模型只读，复用时另存副本。先检查 COMSOL 版本、MCP会话及几何光学模块可用性。
3. 按参数→几何与命名选择→材料→gop→网格→研究设置建模。核壳检查包含与薄壳，介质域分别赋实/虚折射率；本次无损均匀介质的方法不直接适用于吸收、各向异性或GRIN。实际可用接口不足时用Java API补齐再MCP求解，如实说明执行方式。具体节点见[实操方法](references/workflow.md)。
4. 匹配入射方向和偏振，设置光线释放位置、条数、波长与功率。几何光学没有ewfd背景电场输入，平面波幅值需换算辐照度/射线源功率；二维按单位厚度处理，三维按实际照明面积处理。功率单位须核验，不擅自给定作者未报告的激光总功率。
5. 用材料不连续界面处理折射/反射，设置外边界出域方式、次级射线容量及弱分支阈值；简单开放域用Disappear而非PML。曲面可启用几何法向，检查几何和边界解析。设置Ray Tracing输出间隔、终止长度/时间和容差。
6. 用户要求先查看设置时保存未求解模型并停止；用户要求仿真时实际执行研究、等待成功、先保存含解模型。创建求解器不算计算。单个研究的MCP求解可省略study_name，多研究则用工具实际返回的名称。
7. 创建Ray数据集及RayTrajectories图，分别提供primary和包含反射分支的视图；默认Rainbow，相对功率表达式要无量纲并核验图例。重载最终模型，核对实际射线波长、初始条数、源功率合计、解时刻、释放次级射线数量和求解警告。按需导出轨迹CSV；用户只要基本图时不自动启动定量对照。

## 复用资源及参数扫描

[assets/DualEllipseRayBuild.java](assets/DualEllipseRayBuild.java)与[assets/DualEllipseRayDisplay.java](assets/DualEllipseRayDisplay.java)为本机6.3已运行成功的二维双椭圆范例源代码。先读[复用约束](references/core-shell-60-case.md)，复制至本次项目后改ROOT、参数、验证条件、标签和输出路径；不能直接在skill目录执行或写回原项目。Build只配置，Display依赖实际含解模型。

同拓扑改参优先一个模型内扫描；每个参数独立研究/扫描节点，角度写如 `range(30[deg],5[deg],100[deg])`、单位栏deg，几何扫描重建几何及网格。不因参考案例只有一个固定组就自动扫描，也不把波长变化当成几何同比缩放。保留全部参数解，绘图和数据导出明确选择具体外层解；范例Display只验证单组，不能原样处理多参数扫描。

## 结果解释与收录

当前验证过的ComputePower方法计算路径和界面功率分配，没有计算相干波动近场。射线密度、交汇点和gop.Q不能当成ewfd.normE²、PNJ/PH的FWHM或臂数。尺寸只有数个波长时，用射线帮助讨论传播路径，定量近场仍使用波动模型；不从外观宣称两模型严格等价。

有需要才检查射线条数、曲面网格/法向、输出间隔、终止长度和弱分支阈值的敏感性，不从求解成功宣称已收敛。完整路径分析或波动结果对照由用户授权后开展。用户确认模型可行后使用[模型参考库](../comsol-pnj-ph-examples/SKILL.md)收录；求解完成与用户确认分开。
